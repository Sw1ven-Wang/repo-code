# v1.5 → v1.5.1 升级说明

本修复版提高了验收与隐藏评测的可信条件。**不要让旧 Host 与新 Host 同时使用一个 state-root；不要手工改数据库版本或修改签名报告绕过校验。**

## 推荐：使用全新状态目录

1. 停止旧 CLI/SDK/Worker 和它们的子进程；确认没有正在修改工作区的操作。
2. 用旧版本进行离线私有备份，保存整个旧 state-root。备份含源码、记忆及 Host HMAC key，不能公开上传。
3. 安装 `dist/repo_code-1.5.1-py3-none-any.whl` 或从源码安装。
4. 指定新的 `--state-root`，重新冻结必要 Contract、重新登记可信 suite；导入确需的用户经验时重新审阅作用域与来源。
5. 在新环境运行 doctor、离线测试与按需的真实模型 smoke；不要把旧候选成绩视为新版本已通过门禁。

新的 state-root **不等于旧评测数据恢复独立性**。曾用于候选筛选、反馈或学习的题集，仍需要带入曝光历史或更换真正未见的 cohort；不要用新数据库重复同一隐藏集并宣称无污染。

## 状态格式变化

`PRAGMA user_version` 从 15 升级到 16。Store 在事务内重建曝光表的主键，保留所有 family 类别，并为历史 Candidate/Release 回填内容身份、曝光传播和 cohort 预占。旧记录缺少必要引用时升级失败关闭；不会建立一份空账本让隐藏题重新可用。新启动的旧程序会拒绝 schema 16。

这只是**离线结构与历史资格迁移**，不是自动接续所有旧任务的在线升级器。已在运行的旧进程不会因为 PRAGMA 变化而被远程撤权，必须先停止。

本版同时变更了可信 Host/worker 摘要、Grader 版本、Check 可信度字段及 G4 GatePolicy。旧 Release 仍是历史事实，但尝试作为新 Host 的可执行版本时会遇到 `GATE_POLICY_CHANGED` 或 `WORKER_ENVIRONMENT_CHANGED`。旧 Evidence/Gate 不能被复制改摘要后重新使用。

## 尚未解决的恢复材料

先在原版本、原环境完成对账，或保留只读旧状态用于可信人工调查。不要删除未知 Operation、设置假成功、强行释放任务。涉及未知 MCP 外部效果时，服务器退出不等于没有发生写入。

后续如要提供自动跨版本 Run 迁移，需要独立的协议、兼容测试与人工批准；本修复版未提供此能力。

## 知识撤销与备份

撤销使当前 Store 内旧的 Run-pinned 快照也不可读取；撤销后形成的备份恢复后保留撤销记录。**撤销前已经导出的备份、历史原始 blobs 或 Provider 副本不因此自动消失。** 本版不提供跨所有副本的数据销毁保证。
